## 整体结构

单体架构

```
                          ┌─▶ 静态文件（前端）
用户 ── HTTPS ──▶ nginx ──┤
                          └─▶ 微服务 ──▶ 中间件/DB
```

- nginx 部署在宿主机，便于证书续期，负责对接 HTTPS 与请求转发，外部流量统一经由 nginx 进入。
- 前端是静态文件，由 nginx 直接托管，没有前端进程；接口请求由 nginx 按路径前缀转发给微服务。
- 其余组件均在 Docker 容器中运行，容器端口仅在本机监听，位于同一 Docker 网络。

## 组成

|          | 中间件 / DB                                                                 | 微服务                                                                                         |
|----------|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------------------|
| 组件     | MySQL、Redis、Elasticsearch、MinIO、RabbitMQ、Canal、Nacos、Seata、Sentinel | nilo-web、nilo-admin、nilo-storage、nilo-comment、nilo-mq-consumer、nilo-canal-client、nilo-ai |

|---------------|------------------------------------------------------------|

| MinIO         | 提供和保存二进制数据，如图片、视频                         |
| RabbitMQ      | 消息队列                                                   |
| Canal         | 同步 MySQL 数据的组件                                      |
| Nacos         | 注册中心、发布动态配置                                     |
| Seata         | 管理分布式事务                                             |
| Sentinel      | 熔断、限流                                                 |

| 服务              | 职责                                |
|-------------------|-------------------------------------|
| nilo-web          | 用户端接口                          |
| nilo-admin        | 后台管理接口                        |
| nilo-comment      | 评论                                |
| nilo-storage      | 文件存储与处理                      |
| nilo-mq-consumer  | 消息消费（邮件、字幕识别、AI 索引） |
| nilo-canal-client | MySQL 变更同步至 Elasticsearch      |
| nilo-ai           | AI 问答与 MCP 服务                  |

## 发布流程

1. 代码提交后，GitHub 自动执行编译检查（CI）。
2. 通过 **GitHub Actions** **手动触发**发布，并选择需要发布的服务。
3. GitHub 云服务器构建并推送镜像，（部署服务的）服务器拉取镜像并重启对应服务，随后自动执行部署后检查。

详见 [cicd.md](cicd.md)。
