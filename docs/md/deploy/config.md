# 配置管理

本文说明 Nilo 服务端的配置如何分层，以及各层存放的内容

## 目标

- 通过配置中心管理配置，将配置与镜像隔离。
- 密钥不进入代码仓库与镜像。

## 分层

配置分为四层，使用 [Nacos](https://nacos.io/) 作为配置中心：

| 层          | 位置                                  | 内容                                                 |
|-------------|---------------------------------------|------------------------------------------------------|
| 1. 环境变量 | 本地 `.env`；服务器容器的环境变量     | 仅 Nacos 的连接信息：地址、命名空间、账号、密码      |
| 2. 服务配置 | 各微服务 jar 内的 `application.yaml`  | 与环境无关的配置：端口、业务参数，以及开发期的默认值 |
| 3. 公共配置 | Nacos 的 `nilo-common.yaml`           | 各服务共用、随环境变化的配置（见下表）               |
| 4. 专属配置 | Nacos 的 `nilo-<服务名>.yaml`（按需） | 仅覆盖公共配置中不适用于该服务的项                   |

此外，Sentinel 的限流规则也以 JSON 形式存放在 Nacos，由 Sentinel 直接读取。

### 加载顺序

```
读取环境变量 ──▶ 连接 Nacos ──▶ 导入公共配置 ──▶ 导入专属配置 ──▶ 初始化各组件
```

> 提示：
> - Nacos 中的配置会 **覆盖** jar 内的同名配置。
> -
后导入的覆盖先导入的，在配置里把专属配置放在后面（如 [comment 微服务](/nilo-comment/src/main/resources/application.yaml)
），因此专属配置中的同名项优先于公共配置。
> - 修改 Nacos 配置后，建议重启对应服务，组件的开关与连接地址在启动时确定。

## 公共配置的内容

| 类别       | 内容                                                                  |
|------------|-----------------------------------------------------------------------|
| 中间件连接 | MySQL、Redis、RabbitMQ、Elasticsearch、MinIO、Canal 的地址与账号      |
| 服务治理   | Sentinel 控制台地址与规则数据源，Seata 事务服务地址                   |
| 密钥       | AI 服务密钥、邮件授权码、对象存储密钥、服务间调用令牌、后台管理员账号 |
| 环境开关   | 接口文档、组件间 TLS 连接开关、启动横幅                               |

只有评论服务使用专属配置，因为它使用独立的数据库。

## 密钥管理

- `application.yaml` 不含任何密钥，仅保留 Nacos 连接信息。
- `.env` 含 Nacos 账号、密码、地址以及命名空间，不提交，可通过模板 `.env.example` 修改。
- 含密钥的 Nacos 配置不纳入仓库。Nacos 开启登录验证，控制台的访问限制见 [nginx.md](nginx.md)。

## 配置缺失的风险

服务在 Nacos 配置缺失时 **仍会启动**，此时使用 jar 内的默认值，不会报错退出。这会带来两类问题：

- 连接地址回退为默认值，服务虽已启动但无法连接到中间件/DB， **无法正常工作**。
- 开发期的默认值生效，例如接口文档被开启，导致 **服务不安全**。

> 注：第二类问题，如接口文档是否暴露我们会在[部署后检查](security.md)中检验。

## 新增配置项方式

| 配置的特点               | 放置位置                                                          |
|--------------------------|-------------------------------------------------------------------|
| 与环境无关，不含敏感信息 | 服务的 `application.yaml`，随代码发布                             |
| 随环境变化，或属于密钥   | Nacos 的 `nilo-common.yaml`                                       |
| 个别服务需要不同的值     | 新建 `nilo-<服务名>.yaml`，并在该服务的导入列表中排在公共配置之后 |
