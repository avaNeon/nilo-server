# 常见问题

本文记录 Nilo 服务端部署过程中遇到的问题及处理方法

| 现象                                               | 原因                                                                                                 | 处理                                                                                                                                                             |
|----------------------------------------------------|------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 启动微服务时报网络 `declared as external` 但不存在 | 中间件尚未启动，或已被 `down` 删除，网络由中间件的 Compose 创建                                      | 先启动中间件；`up` 操作会按顺序启动                                                                                                                              |
| 微服务报 `Failed to get available servers`         | 启动时读到的 Nacos 配置为空（Nacos 尚未就绪，或命名空间、账号有误），Seata 地址回退为默认值          | 确认 Nacos 可用且配置存在，重启该服务。整体重启时用 `down` 再 `up`，`restart` 不会等待中间件初始化                                                               |
| 部署后检查报 `该路径未被阻塞` ，check 失败         | 生产配置未生效：`knife4j.enable` 与 `knife4j.production` 需同时为 `true`；或修改配置后未重启服务     | 核对 Nacos 中的配置，重启服务，再执行 `check`                                                                                                                    |
| 部署后检查报 `服务仍然没有响应`                    | 服务启动失败或启动过慢                                                                               | 查看日志；确认配置存在；等待后单独执行 `check`                                                                                                                   |
| 发布时 `server` 任务报 `i/o timeout`               | 服务器防火墙未放行 SSH 入口。GitHub 云服务器的出口 IP 不固定，无法按来源 IP 限制                     | 放行 SSH 入口 ( 0.0.0.0/0 ) 。登录仅限密钥，且部署账户受限，见 [security.md](security.md)                                                                        |
| Actions 日志中出现大量 `err:` 开头的行             | **这不是报错**，SSH 步骤把标准错误输出标为 `err:`，Docker 拉取镜像的进度写在标准错误中，并不代表失败 | 以任务的最终状态与末尾的报错为准                                                                                                                                 |
| 容器反复重启                                       | 可能超出内存上限被系统终止，也可能是连接不到中间件/DB，或者是配置失败等等                            | 先查看微服务日志输出。如果是OOM：`docker inspect -f '{{.State.OOMKilled}}' <容器名>` 为 `true` 时，调整堆大小与内存上限 。如果是其他问题针对性处理（自己想办法） |
| Seata 启动即退出，日志提示脚本语法错误             | 使用了 `JAVA_TOOL_OPTIONS`                                                                           | 改用专用环境变量，见 [middleware.md](middleware.md)                                                                                                              |
| 申请证书时 certbot 报错，找不到某个域名的证书文件  | nginx 配置里已有站点引用了尚未签发的证书，nginx 配置校验不通过，certbot 无法借助 nginx 完成验证      | 先把该站点的配置文件移出 nginx 的配置目录，签发证书后再放回并重载                                                                                                |
| nginx 报 `conflicting server name`，访问域名落到默认页 | 同一个域名在多个配置文件中重复定义。常见于 certbot 自动修改默认站点时，在其中生成了同名的站点块    | 只保留一处定义，删除重复的站点块，校验配置后重载，见 [nginx.md](nginx.md)                                                                                        |
