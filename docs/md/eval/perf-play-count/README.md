## 主要结论

播放统计链路，每秒 5000 次、热点分布，三次运行的范围：

- 把写库移出请求线程（V1）消除了数据库连接池的瓶颈，放行吞吐提升 1.6～2.9 倍。
- 消费端批量写入（V2）使 MySQL 语句数降至 V1 的 1/41～1/59，写入完成延迟由 61～179 秒降至 5 秒的发送周期以内。
- 两步合计，每个放行请求的 CPU 减少 57%～72%；消费端并行写入（V3）在当前负载下没有可测的收益。
- 压测环境引入 nginx 后，nilo-web 的全量 GC 由 140 次降为 0 次。
